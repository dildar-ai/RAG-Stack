## 1. What this product is

**RAG Stack** is a multi-tenant "chat with your documents" SaaS:

1. A user signs in (Supabase Auth), creates a **workspace**, and uploads PDFs.
2. Each PDF is parsed into **merged text chunks** (adjacent blocks combined in
   reading order, running headers/footers deduplicated) carrying page + bounding-box
   coordinates, then embedded into a **Qdrant** vector collection.
3. The user asks questions in the **Playground**; the answer is generated by
   **Groq's LLM** strictly from retrieved chunks. Every statement ends in a `[n]`
   citation marker, and the pipeline keeps only the sources the model actually used —
   markers and source chips are renumbered so they match 1:1.
4. Clicking a citation chip opens the original PDF on **exactly that page** and
   highlights the source region.
5. Chat history and citations persist in Postgres, so old conversations still resolve
   citations later (via freshly-minted signed URLs).
6. Every workspace can enable a **public embeddable widget** — an iframe chatbot for
   the owner's own website that answers from their documents, without visitors needing
   accounts.

### Tech stack at a glance

| Layer | Technology | Where |
|---|---|---|
| Frontend | Next.js 16 (App Router, Turbopack), React 19, Tailwind CSS 4, lucide-react, react-pdf | `apps/web` |
| Backend API | FastAPI (Python 3.10), LangChain + Groq, PyMuPDF, sentence-transformers | `apps/api` |
| Auth + DB + File storage | Supabase (Auth, Postgres with RLS, private Storage bucket) | external service |
| Vector database | Qdrant (cloud or self-hosted) | external service |
| LLM | Groq (`openai/gpt-oss-20b` by default; `120b` variant is smarter but slower) | external service |
| Embeddings | `all-MiniLM-L6-v2` run **locally** in the API process (free, no API key) | in-process |
| Monorepo tooling | Turborepo + npm workspaces | repo root |

## 3. How a request flows (the important part)

### 3.1 Uploading a PDF — `POST /api/v1/upload`

```
Browser ──(Bearer JWT + file)──▶ FastAPI
  1. auth: validate token against Supabase /auth/v1/user      (services/auth.py)
  2. auth: verify the user OWNS workspace_id                   (workspaces table)
  3. rate limit: 10 uploads/min/user                           (services/rate_limit.py)
  4. validate: content-type, .pdf extension, %PDF- magic bytes, ≤ MAX_UPLOAD_MB
  5. parse: PyMuPDF blocks → merged reading-order chunks with
     union bboxes; short lines repeated on 3+ pages are      (services/pdf_parser.py)
     treated as headers/footers and collapsed to first occurrence
  6. embed: all-MiniLM-L6-v2 batch encodes every chunk        (services/embeddings.py)
  7. upsert: vectors + payload {workspace_id, document_id,
     page, bbox, text} into Qdrant in batches of 100
  8. store: raw PDF → private Supabase bucket at {workspace_id}/{document_id}.pdf
  9. record: insert row into documents table (status=Processed)
```

Every step after 7 has **compensation cleanup**: if storage or the DB insert fails,
the already-written vectors (and file) are deleted so no orphan state remains.

Vector `payload.workspace_id` is the tenant firewall — it is written on every point
and enforced on every search. Qdrant knows nothing about auth; the API never builds
an unfiltered query.

### 3.2 Asking a question — `POST /api/v1/chat`

```
1. Bearer token validated → workspace ownership verified → 30 req/min limit
2. query embedded (same local model)
3. Qdrant over-fetches 12 candidates filtered to workspace_id; chunks scoring
   below RAG_MIN_SCORE are dropped, top 6 survive               (services/rag.py)
4. filenames + 15-min signed PDF URLs resolved from Supabase for the cited docs
5. Prompt = SYSTEM_PROMPT + <context> blocks labelled "[n] (page P)" + last 6
   history turns + query. The model must answer ONLY from context, cite every
   statement with its bare [n] marker, and treat title/header/role lines as
   valid evidence (company name, CEO, …)
6. Groq generates the answer (temperature 0)
7. Citation grounding: the raw output is Unicode-normalized first (gpt-oss emits
   fullwidth brackets / narrow no-break spaces that silently break [n] parsing),
   cited markers are extracted, out-of-range markers are stripped, and answer +
   chips are renumbered so marker [k] always equals chip [k] and its page
8. Response: { answer, citations[{marker, document_id, filename, page, bbox,
   text, pdf_url}] } — the frontend stores both in `messages`
```

`retrieve_and_answer()` in [rag.py](apps/api/services/rag.py) is the **single shared
pipeline** used by both the authenticated dashboard and the public widget — behaviour
can't drift between the two surfaces.

### 3.3 Opening a citation — `POST /api/v1/documents/url`

Citations stored in old chats only keep `document_id`/page/bbox. On click, the
frontend requests a **fresh signed URL** for the private bucket object, so links
never go stale and the PDF is never publicly readable. The viewer then renders that
page and overlays the bbox rectangle.

### 3.4 The public widget — `GET /api/v1/widget/config`, `POST /api/v1/widget/chat`

Anonymous iframe visitors present `X-Publishable-Key` instead of a user token:

- The key maps to exactly one row in `widget_settings` → one workspace. It can only
  *ask questions*; it cannot list documents, upload, delete, or touch other tenants.
- Per-key origin allow-list (`allowed_origins`) blocks misuse of stolen keys from
  unknown domains; direct server-to-server calls without an Origin header still pass.
- `allow_source_access` decides whether answers include signed PDF URLs.
- Rate limited per workspace+client-IP (default 20/min) because it is anonymous.
- The widget page (`/widget/<key>`) is served with `frame-ancestors *`; every other
  route of the app refuses framing.

## 4. Data model (Supabase Postgres)

All of this is created by running [`schema.sql`](schema.sql) once.

| Table | Purpose | Key columns |
|---|---|---|
| `workspaces` | Tenant root | `id`, `name`, `owner_id → auth.users` |
| `documents` | Ingested PDFs | `id`, `workspace_id`, `filename`, `storage_path`, `status` |
| `profiles` | Onboarding data | `id → auth.users`, `company_name`, `industry` |
| `chats` / `messages` | Playground history | `messages.citations` is JSONB (page/bbox/text per source) |
| `widget_settings` | One row per workspace widget | `publishable_key` (UNIQUE), `is_enabled`, `allow_source_access`, `welcome_message`, `allowed_origins text[]` |

**Storage bucket:** `documents`, **private** — objects live at
`{workspace_id}/{document_id}.pdf` and are only reachable via signed URLs (server)
or workspace-folder-scoped RLS policies (owner).

**RLS everywhere:** every table policy checks `auth.uid()` ownership. The API's
service-role key intentionally bypasses RLS, but *every* query it makes is first
gated by `ensure_workspace_ownership()`.

**Vector store:** one shared Qdrant collection `documents` (384-dim cosine), every
point payload carries `workspace_id` and `document_id`, with keyword indexes on
**both** keys — `workspace_id` for fast filtered search and `document_id` because
Qdrant ≥1.13 rejects delete-by-filter on unindexed fields. The API creates both
automatically at startup.

## 6. Security & operational hardening (already built in)

- **Tenant isolation is checked before any data access** on every endpoint, including
  reads of the documents table and Qdrant filters.
- **No secrets in the browser:** the anon key is the only Supabase credential client-side;
  the service-role key and Groq/Qdrant keys live only in the API environment.
- **Token validation is Supabase-side** (`/auth/v1/user`), so signing-algorithm or key
  rotation on Supabase never breaks the API; results cached 60s.
- **Error hygiene:** 5xx responses are generic + logged with full detail; anything
  containing credential-looking substrings is redacted; unhandled exceptions never
  leak stack traces.
- **Request IDs:** every response carries `X-Request-Id`, and every log line includes
  it — trace one user action end-to-end.
- **Input limits:** PDF magic-byte check, 25 MB default cap, query length caps
  (4000/2000 chars), history turn caps, chunk char caps.
- **Fail-fast boot:** with `APP_ENV=production`, a missing required secret aborts
  startup instead of serving broken traffic.
- **Rate limiting** per user/IP with `Retry-After` headers (in-process — see §9).
- **Docker:** pinned deps, non-root user, embedding weights baked into the image,
  healthcheck, `.env`/`venv` excluded from the build context.

## 7. Which API keys go where (complete map)

You need accounts/keys from **three providers**, plus one that's free/local:

| Provider | What you create | Used by | Where you paste it |
|---|---|---|---|
| **Supabase** | Project → get **URL**, **anon key**, **service-role key** | web (anon) + api (all three) | see below |
| **Qdrant** | Cloud cluster → **URL** + **API key** (or run Docker locally) | api only | `apps/api/.env` |
| **Groq** | Console → **API key** | api only | `apps/api/.env` |
| sentence-transformers | nothing — model runs locally | api | no key needed |

### Exact placement

**`apps/api/.env`** (from `.env.example`) — the API needs:
```
SUPABASE_URL=...                  # https://<ref>.supabase.co
SUPABASE_ANON_KEY=...             # same anon key the browser uses
SUPABASE_SERVICE_ROLE_KEY=...     # ⚠ SERVER ONLY, never goes to the frontend
QDRANT_URL=...                    # https://<cluster>.region.cloud.qdrant.io:6333
QDRANT_API_KEY=...
GROQ_API_KEY=...
ALLOWED_ORIGINS=http://localhost:3000,https://<your-vercel-app>.vercel.app

# Optional tuning — sensible defaults are baked into the code:
#GROQ_MODEL=openai/gpt-oss-20b          # or openai/gpt-oss-120b
#RAG_TOP_K=6  RAG_MIN_SCORE=0.10  PDF_CHUNK_MERGE_CHARS=700
```

**`apps/web/.env.local`** (from `.env.example`) — the browser needs only:
```
NEXT_PUBLIC_SUPABASE_URL=https://<ref>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon key>
NEXT_PUBLIC_API_URL=http://127.0.0.1:8000    # or your deployed API URL
NEXT_PUBLIC_MAX_UPLOAD_MB=25
```

> **The one rule that keeps you safe:** the `sb_secret_…` / service-role key and the
> Groq/Qdrant keys exist **only** in the API environment. `NEXT_PUBLIC_*` variables
> are compiled into the JS bundle — never put a secret in one.

### Where to find each value

- **Supabase URL + anon + service keys:** Dashboard → your project →
  *Project Settings → API* (or *Connect*). Project Settings → *Authentication →
  URL Configuration* → add `http://localhost:3000/auth/callback` and your deployed
  `https://<app>/auth/callback` to Redirect URLs.
- **Qdrant:** cloud.qdrant.io → create cluster → *API endpoint* + *API key*
  (enable authentication). Local alternative: `docker run -p 6333:6333 qdrant/qdrant`
  with `QDRANT_URL=http://localhost:6333` and no API key.
- **Groq:** console.groq.com → *API Keys* → create key.

## 8. Run locally, then deploy

### 8.1 Local run (all three things must be up)

```powershell
# 0) One-time: Supabase → SQL Editor → paste schema.sql → Run

# 1) API
cd apps/api
Copy-Item .env.example .env        # fill in ALL keys from §7
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn main:app --reload --port 8000

# 2) Web (new terminal)
cd apps/web
Copy-Item .env.example .env.local  # fill in Supabase + API URL
npm install                        # from repo root also works (workspaces)
npm run dev                        # http://localhost:3000
```

Sanity check: browse `http://127.0.0.1:8000/health/ready` — all three checks should
read `true` before you touch the UI.

Optional demo login (instead of signing up repeatedly):

```powershell
cd apps/api; .\venv\Scripts\Activate.ps1
python seed_demo_user.py    # creates demo@ragstack.dev + profile + workspace
```

Sign-up without email delivery: Supabase Dashboard → *Authentication → Providers →
Email* enabled, and (for dev) disable "Confirm email" so login works instantly.

### 8.2 Deploy the web app → Vercel

Easiest path: the `vercel-deploy` flow, or manually:

1. Push this repo to GitHub, *Import* it in Vercel.
2. Framework preset **Next.js**; Root directory stays `.` — select the **`web`**
   project (Turborepo auto-detection handles it; build command `turbo build` works
   too if you set it up as a monorepo import).
3. Set **Environment Variables** for the `web` app:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `NEXT_PUBLIC_API_URL` = your deployed API URL (step 8.3)
   - `NEXT_PUBLIC_MAX_UPLOAD_MB=25`
4. Add the production callback `https://<your-app>.vercel.app/auth/callback`
   to Supabase Redirect URLs.

### 8.3 Deploy the API → any Docker host

Options: Render / Railway / Fly.io / a VPS / Hugging Face Spaces (Docker SDK).

```powershell
docker build -t rag-api ./apps/api
```

- Pass all variables from `apps/api/.env` as **platform secrets** (never bake them
  into the image).
- The image listens on `$PORT` (default **7860**). On platforms with a fixed port,
  set `PORT` accordingly.
- Set `APP_ENV=production`, `LOG_LEVEL=INFO`, and `ALLOWED_ORIGINS=https://<your-app>.vercel.app`.
- Sizing: give the container **≥ 1 GB RAM / 1 vCPU** — the embedding model is ~90 MB
  and batch-encodes on CPU. Keep `WEB_CONCURRENCY=1` unless you scale memory.
- Health check path: `/health`; readiness: `/health/ready`.

**Hugging Face Spaces variant** (free-ish): create a Docker Space, upload `apps/api`
contents, and set the same env vars in Space settings → Variables (Secrets for keys).
Port 7860 is already the default — the Dockerfile was written for it.

### 8.4 Post-deployment checklist

- [ ] `https://<api>/health/ready` shows qdrant/supabase/groq all `true`
- [ ] `https://<api>/docs` returns **404** (proof `APP_ENV=production` took effect)
- [ ] Sign up from the live site → onboarding creates a workspace
- [ ] Upload a text-based PDF → appears in Documents with chunk count
- [ ] Ask a question → answer + clickable citation → viewer highlights the region
- [ ] Reload the page, open an old chat → citations still open (signed URLs re-minted)
- [ ] Workspace Settings → enable widget → paste the iframe snippet into any page →
      ask from the widget; try a wrong origin with the allow-list enabled
- [ ] Delete a document → its vectors stop answering, file 404s, row gone

## 9. Known limitations & what to do next

| Area | Current state | When it matters |
|---|---|---|
| Rate limiting | In-process memory; per replica | Scaling to >1 API replica → move to Redis (see `services/rate_limit.py` header comment) |
| Auth cache | In-process 60s token cache | Same: multi-replica → Redis, or accept the per-replica cache (harmless) |
| Ingestion | Synchronous upload→embed→store | Huge PDFs → background queue (arq/Celery) + `status=Processing` polling UI |
| Embeddings | Local MiniLM (good, free) | Domain-specific recall → try a bigger model or provider embeddings |
| OCR | Text-layer PDFs only | Scanned PDFs → add an OCR step (e.g. `rapidocr`) before parsing |
| Team/Billing/Integrations pages | UI scaffolding | Wire to Stripe / Supabase team invites when you monetize |
| Qdrant collection | Single shared `documents` collection, payload-filtered | Fine to ~millions of points; per-tenant collections only if isolation requirements change |

## 10. Troubleshooting quick table

| Symptom | Likely cause | Fix |
|---|---|---|
| Web shows "Cannot reach the RAG API server" | API down or `NEXT_PUBLIC_API_URL` wrong | Check `/health`; redeploy with correct URL |
| Upload: "not a valid PDF" / "Only PDF files are supported" | Bad file or proxy stripped content-type | Real PDFs start with `%PDF-` |
| Upload: "Scanned/image-only documents require OCR" | No text layer in PDF | Needs OCR (§9) |
| Chat 401 right after login | Session expired | Sign in again; tokens refresh via `proxy.ts` |
| Chat 429 | Rate limit | Wait the `Retry-After` seconds or raise `RATE_LIMIT_*_RPM` |
| Widget "This assistant is unavailable" | Key disabled/unknown | Re-enable in Workspace Settings; regenerate key |
| Widget "Origin not allowed" | `allowed_origins` set, embedding page differs | Add the exact `scheme://host` |
| Citation viewer blank | File deleted or storage error | Re-upload; check API logs for the request id |
| API won't boot: "Missing required environment variable(s)" | `APP_ENV=production` + unset secrets (by design) | Set all four required vars |
| `next build`: middleware/proxy conflict | Both `middleware.ts` and `proxy.ts` present | Keep only `proxy.ts` (already resolved) |
| Upload: "Vector store is temporarily unavailable" | Qdrant unreachable — commonly the cloud **IP allow-list** rejecting your network | Add your public IP (or clear the list) in the Qdrant console |
| Chat: Groq 403 "Access denied. Please check your network settings." | Cloudflare blocking your IP/VPN — not a key problem | Disable VPN / change network; cloud hosts are usually unaffected |
| Chat: 404 `model_not_found` | Groq retired the model in `GROQ_MODEL` | `GET https://api.groq.com/openai/v1/models` with your key, pick a listed model |
| Nested dashboard routes 404 | `next dev` and `next start` share the `.next` folder | Delete `.next`, then run **one** mode (rebuild before `start`) |
| Back button shows dashboard after logout | Browser restores the page from bfcache | Handled: client session guards + `Cache-Control: no-store` on `/dashboard` |
| Delete document → 500 | Qdrant ≥1.13 needs a payload index on `document_id` | Handled: index created automatically at startup |
